# 联机房间加入与准备修复 · 2026-10-17

修复直接输入房间号时使用默认回环地址连接本机的问题：加入前使用 LAN 广播查找匹配房间的真实主机 IP 和端口。搜索列表入口直接使用被选房间的完整地址，避免重新按房间号推导端口；高级页填写的地址/端口仍可用于直连。查找可取消，未找到时停留在可操作页面并显示明确原因，不再进入一个未连通的假房间。

联机主列表、搜索列表、高级页及房间页接入现有菜单鼠标意图链，绘制与命中共用行几何，支持悬停、左键确认、右键返回和滚轮选择，房间内准备、取消准备、更换选择和离开均走原有逻辑。空白处点击不会误触已选中的准备行。

房间显示分别表达等待加入、连接中、选择同步中和未准备。准备被阻止时显示原因；加入方连接或选择同步超时会结束等待并显示提示。客户端只从 connected_to_server 发送一次握手，避免 peer_connected(1) 再发送一遍造成错误密码重复拒绝。密码验证、双方准备、合法机体限制和房主提交开局机制保持有效。

验证：联机相关筛选套件 427 PASS / 0 FAIL；鼠标菜单套件 235 PASS / 0 FAIL。真实同机双进程 ENet/UDP + 广播测试覆盖：输入房间号自动解析实际网卡 IP；广播的有效自定义端口；实际菜单鼠标准备；双方收到准备后提交同一对局并走菜单出击出口；错误密码主机拒绝、加入方退出；查找取消不延迟加入；连接成立但选择未齐的同步超时退出。新探针为 tests/lan_room_live.tscn，参数 host/guest 和 case=code/custom/badpass/cancel。重型实战场景加载在探针中由菜单出击出口标记替代，未做跨两台电脑、防火墙或互联网穿透验证，未做全项目回归。

验证日志和修改前备份：本 Codex 会话 work/lan_ready_fix/。最初旧式固定延迟双进程驱动出现启动时序干扰；最终测试等待房主实际监听后再启动加入方，避免误判连接失败。
